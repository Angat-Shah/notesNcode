# Contributing to notesNcode

A commitment to academic excellence drives this archive. Thank you for investing your time and expertise to strengthen it.

## Principles

- **Accuracy & clarity**: Ensure implementations are correct, commented where non-obvious, and follow language best practices. Notes must be in your own words—no plagiarism or proprietary material.
- **Structural consistency**: Align with the existing hierarchy (Semester / Subject / Type). Use descriptive filenames (e.g., `DAA_Lab_Manual_v1.pdf`).
- **Quality documentation**: Prefer Markdown or searchable PDFs. Add a short description for new resources to give readers context.

## Contribution workflow

1. **Fork & clone**: Work from your fork of the repository.
2. **Branch**: Use a descriptive branch name (e.g., `add/semester-5-os-notes`, `fix/algo-lab-logic`).
3. **Commit**: Write concise, imperative commit messages (e.g., `Refactor: Update sorting algorithms in C++`).
4. **Pull request**: Open a PR summarizing changes and why they matter. Highlight any new resources, corrections, or reorganizations.

## What to include in a PR

- Scope summary: What changed and which semesters/subjects it touches.
- Resource context: One–two sentences describing any new files (notes, labs, assignments, datasets).
- Testing/verification: Mention any checks you ran (builds, linting, previews).

## Content guidelines by type

- **Notes & study material**: Clear synthesis, well-formatted headings/bullets; cite references briefly if applicable.
- **Lab records**: Complete programs, outputs/screenshots if relevant, and viva-style Q&A when available.
- **Assignments**: Final solutions with explanations where helpful; keep academic integrity in mind.
- **Question banks**: Organized by topic; include solutions or reasoning when possible.
- **Datasets**: Describe source, size, labeling, and intended use. Include a README in the dataset folder when adding new data.

## Style & formatting

- Markdown: Use meaningful headings, lists, and code fences. Keep line lengths reasonable for readability.
- Code: Follow language-specific style guides; keep diffs focused and purposeful.
- Filenames: Prefer kebab-case or descriptive PascalCase; avoid ambiguous names like `final.docx`.

## Respectful collaboration

Every contribution—whether fixing a typo or adding a full subject archive—helps peers and successors. Please keep discussions constructive, focused, and considerate.

Thank you for helping preserve and elevate this academic archive.
